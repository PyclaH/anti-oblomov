# Анти-Обломов

Android-приложение, которое помогает старшеклассникам и студентам меньше отвлекаться на соцсети: блокирует выбранные приложения по расписанию или таймеру и показывает вместо них мотивирующую цитату из русской классики.

**Автор:** Руслан Шашков, Гимназия №25 г. Иркутска
**Школьный проект, 2026**

> «Теперь или никогда!» — И. А. Гончаров, «Обломов»

## Что умеет (план)

| Раздел | Что делает |
| --- | --- |
| Главная | Идёт ли сейчас блокировка; сравнение «было / стало» — время в соцсетях до установки и сейчас. Если время сэкономлено — ненавязчивое предложение поблагодарить автора через Sponsr |
| Расписание | Время блокировки на каждый день недели, с перерывами |
| Таймер | Разовая блокировка, например на 3 часа |
| Приложения | Выбор из установленных приложений, какие блокировать |
| Экран блокировки | Логотип и цитата вместо заблокированного приложения |

Готовы блокировка, расписание, таймер и выбор приложений; дальше — онбординг и «Было / стало» (план ниже).

## Технологии

- Kotlin + Jetpack Compose (Material 3)
- Минимальная версия: Android 8.0 (API 26)
- Все данные хранятся только на телефоне — без серверов и аккаунтов

## Поддержка автора

Приложение полностью бесплатное. Благодарность автору — добровольная, через [Sponsr](https://sponsr.ru/): ссылка открывается в браузере, оплата проходит на стороне Sponsr. Донат ничего не открывает и не влияет на работу приложения.

При публикации в RuStore Sponsr нужно задекларировать в консоли как сторонний платёжный сервис (требования RuStore, п. 9.1).

Когда показывать предложение поблагодарить — см. спецификацию «Было / стало», п. 6.

## Спецификация: раздел «Было / стало»

Статус: **реализовано на шаге 7** (решения от 25.10.2026 — ниже). Блок на главном экране, который показывает, сколько времени пользователь возвращает себе благодаря приложению.

### 1. Метрика

Сравниваем **среднее время в день** в приложениях из списка блокировки.

| Показатель | Как считается |
| --- | --- |
| **До установки** | Среднее в день в заблокированных приложениях по полным дням до установки (до 7) |
| **Сегодня** | Время в заблокированных приложениях с полуночи |
| **Сэкономлено сегодня** | До установки − сегодня (каждый день) |
| **С установки** | Среднее в день по полным дням после установки |
| **Накоплено** | Σ (до установки − время за день) по дням после установки; в часах и учебных днях (1 учебный день = 8 ч) |
| **Вехи** | Неделя, две недели, 1–12 месяцев: сравнение за весь срок вехи |

«Установка» — день, когда выдан доступ к статистике; сам он не считается.

Правила:

- **Если дней меньше 7** — просто среднее по доступным дням, до и после (решение от 25.10.2026). Сравнение по вехам — с 7 дней: в неделе одинаково представлены будни и выходные.
- **День установки не учитывается** ни в «было», ни в «стало» — он неполный.
- **«Было» фиксируется один раз** и дальше не пересчитывается.
- **Приложения для статистики выбираются отдельно** (решение от 25.10.2026): выпадающий список в блоке «Было / стало» — включённые приложения и поиск; пока его не меняли, он совпадает со списком блокировки; «Активировать все» — все несистемные приложения. «Было» и «стало» всегда считаются по *текущему* выбору, поэтому
  **при первом запуске сохраняем полный снимок** истории за 7 дней по *всем* приложениям (пакет → минуты по дням) в локальное хранилище. Иначе для приложения, добавленного в список позже, «было» не посчитать: система к тому времени удалит старые данные.
- **Если истории до установки меньше 7 дней** (новый телефон, сброс) — «до установки» считаем по доступным полным дням и подписываем: «по 4 дням до…». Нет ни одного дня — пишем, что сравнивать не с чем.

### 2. Источник данных

- Системная статистика Android `UsageStatsManager` — та же, что в «Цифровом благополучии».
- Нужно специальное разрешение **«Доступ к истории использования»** (`PACKAGE_USAGE_STATS`) — пользователь включает его в настройках; это шаг онбординга.
- Время по дням считаем по событиям `queryEvents` (переход приложения на передний план и уход с него) с границами суток **по местному времени** — дневные «корзины» `queryUsageStats` не всегда совпадают с полуночью.
- Система хранит подробную историю ограниченное время (по документации: по дням — около недели), поэтому:
  - «было» доступно сразу при установке, но не больше чем за ~7 дней;
  - для «стало» и «накоплено» приложение **каждый день сохраняет** собственную запись (дата → минуты по приложениям) и не зависит от того, сколько хранит система.
- Все данные остаются на телефоне.
- Известные погрешности:
  - при попытке открыть заблокированное приложение оно на ~1 секунду попадает на передний план — эти секунды засчитываются; приемлемо;
  - на Xiaomi/HyperOS статистика может вести себя нестандартно — проверить на Poco на неделе 7.

### 3. Что показываем

| Когда | Экран |
| --- | --- |
| До выдачи доступа | Объяснение и кнопка «Включить доступ» |
| С первого дня | Сегодня · до установки (в день) · сэкономлено сегодня; всё экранное время |
| С первого полного дня после установки | + в среднем с установки, сэкономлено в среднем, всего вернул себе |
| С 7 дней | + веха: неделя, две недели, месяц… год |

### 4. Длительное использование (учебный год)

Одна цифра «−1 ч 40 мин в день» быстро перестаёт замечаться, а «было» со временем устаревает. Поэтому:

- **Главная цифра — накопленный итог**: «С октября ты вернул себе 63 часа — это 8 учебных дней» (учебный день = 8 часов). Она растёт и не обесценивается.
- **Вехи**: неделя, две недели, месяц, два месяца… год — сравнение за весь срок вехи.
- **График по неделям**: время в заблокированных приложениях, линия «было» для сравнения — видно, если привычка возвращается.
- **Подпись к «было»**: «по сравнению с неделей до установки (октябрь)» — честно показываем, с чем сравниваем.

### 5. Честность цифр

- Рядом с экономией показываем **общее экранное время** (было / стало). Если общее время не снизилось — время просто перетекло в незаблокированные приложения; это показываем, а не прячем.
- Отрицательную экономию не скрываем: «На этой неделе больше, чем до установки» — без упрёков.
- Не пишем «приложение сэкономило» — пишем «ты вернул себе»: заслуга пользователя, и это точнее (эффект приложения отдельно не измерен).

### 6. Предложение поблагодарить автора

Панель `ThankAuthorCard` на главной **видна всегда** — ненавязчиво, под «Было / стало» и над карточкой службы (решение от 25.10.2026). Если экономия уже ≥ 15 минут в день, панель её упоминает. Кнопка «Поддержать на Sponsr» открывает [sponsr.ru/anti_oblomov](https://sponsr.ru/anti_oblomov/) в браузере.

Никогда не показываем на экране блокировки и не связываем с отзывом в RuStore.

### 7. Ограничения для исследования и защиты

- **Нет контрольной группы** — разница «было − стало» не доказывает эффект приложения.
- **Возврат к среднему**: приложение обычно ставят, когда сидение в телефоне особенно надоело, поэтому неделя «было» часто выше обычного уровня — разница завышает эффект.
- **Сезонность**: каникулы, экзамены, расписание меняют время в соцсетях независимо от приложения.
- **Перетекание** в незаблокированные приложения — см. п. 5.

### 8. Хранение (для разработки)

| Данные | Когда пишется |
| --- | --- |
| `usage.json` → `start`, `before`: день установки + секунды по каждому приложению за каждый из ≤ 7 дней до | Один раз, при первой выдаче доступа |
| `usage.json` → `after`: дата → секунды по каждому приложению (экранное время считается из них) | Главный экран и служба блокировки (раз в час) дописывают прошедшие дни |

## Как запустить на телефоне (Windows + Poco / HyperOS)

### 1. Установить программы на компьютер

1. **Android Studio** — скачать с [developer.android.com/studio](https://developer.android.com/studio) и установить с настройками по умолчанию. При первом запуске пройти мастер до конца — он скачает Android SDK. Java отдельно ставить не нужно.
2. **Git для Windows** — скачать с [git-scm.com](https://git-scm.com/download/win), установить с настройками по умолчанию.

### 2. Открыть проект

1. Запустить Android Studio.
2. На стартовом экране нажать **Get from VCS** (или в меню **File → New → Project from Version Control**).
3. В поле **URL** вставить `https://github.com/PyclaH/anti-oblomov.git`, выбрать папку, нажать **Clone**.
   Если Android Studio попросит войти в GitHub — войти под аккаунтом **PyclaH**.
4. Дождаться, пока внизу закончится **Gradle sync** (первый раз — 5–15 минут: скачиваются библиотеки).
   Если Android Studio предложит обновить версию Android Gradle Plugin — можно согласиться.

### 3. Подготовить телефон Poco (HyperOS)

1. **Включить режим разработчика:** Настройки → О телефоне → семь раз нажать на **Версия ОС (HyperOS)**. Появится «Вы стали разработчиком».
2. **Открыть параметры разработчика:** Настройки → Расширенные настройки → **Для разработчиков**.
3. Включить:
   - **Отладка по USB**;
   - **Установка через USB** — без этого HyperOS не даст поставить приложение (ошибка `INSTALL_FAILED_USER_RESTRICTED`). Может потребоваться войти в Mi-аккаунт и вставленная SIM-карта;
   - **Отладка по USB (настройки безопасности)** — если такой пункт есть.
4. Подключить телефон к компьютеру кабелем, который передаёт данные (не только заряжает).
5. На телефоне в окне «Разрешить отладку по USB?» поставить галочку **Всегда разрешать с этого компьютера** и нажать **ОК**.

> Названия пунктов в разных версиях HyperOS могут немного отличаться — ищите похожие по смыслу.

### 4. Запустить приложение

1. В Android Studio вверху, в списке устройств, выбрать свой телефон (например, *Xiaomi …*).
2. Нажать зелёную кнопку **▶ Run** (или `Shift + F10`).
3. Через минуту на телефоне откроется «Анти-Обломов» с четырьмя вкладками.

**Телефон не появляется в списке?**
- Проверить, что кабель передаёт данные: попробовать другой кабель или порт.
- В шторке уведомлений телефона выбрать режим USB **Передача файлов**.
- Отключить и снова включить «Отладку по USB», переподключить кабель.
- Если не помогло — установить драйвер: в Android Studio **Tools → SDK Manager → SDK Tools → Google USB Driver**.

### 5. Получать обновления кода

Когда в репозитории появляются изменения: в Android Studio **Git → Pull** (или `Ctrl + T`), затем снова **▶ Run**.
